Quick Manual for AHK + WPF

Practical guide to controlling WPF controls from AutoHotkey 1.1 using the project engine. The idea is simple: AHK handles the logic and WPF handles the UI.

Events with ui.OnEvent() Updates with ui.Update() Rows with AddItem / AddRow Selection parsing in ListView Themes with ui.SetTheme() Focus with ui.Focus()

1. Core Concept

Every WPF control is identified by its x:Name. This is the name you use from AHK to read states, change properties, or receive events. 

ui := new XAMLGUI("Demo_Login.xaml")
ui.OnEvent("BtnLogin", "Click", "Login_Event")
ui.Show()

2. Main Syntax

The most important method is ui.Update(control, property, value). For lists, the engine understands actions like AddItem, ClearItems, RemoveSelected, and UpdateSelected. 

ui.Update("TxtUser", "Text", "admin")
ui.Update("BtnLogin", "Content", "Login")
ui.Update("TxtStatus", "Foreground", "#00FF00")
ui.Focus("TxtUser")
ui.Update("LvTasks", "AddItem", "1|Task 1|Daily|08:00|Active|Yes")
ui.Update("LvTasks", "UpdateSelected", "1|Task 1|Weekly|10:30|Active|Yes")

3. What Each Method Does

Method Usage Example
ui.OnEvent() Registers an event for a control. ui.OnEvent("BtnLogin", "Click", "Login_Event")
ui.Update() Changes a property or state of the control. ui.Update("TxtUser", "Text", "admin")
ui.AddRow() Shortcut to add a row to a ListView without manually building the pipe-separated string. ui.AddRow("LvTasks", "1", "Task 1", "Daily", "08:00")
ui.Focus() Sets focus to a specific control. ui.Focus("TxtPass")
ui.SetResource() Changes a global color resource. ui.SetResource("Accent", "#00A3FF")
ui.SetTheme() Applies a complete theme (e.g., "Dark", "Light"). ui.SetTheme("Dark")
ui.SetWindowProp() Modifies the main window properties. ui.SetWindowProp("Title", "My App")
ui.Update("Grid", "AddColorItem", colors) Applies per-cell background colors to the last added row in a DataGrid. Colors are pipe-separated ("#RRGGBB|#RRGGBB|..."), one per column. ui.Update("GridData", "AddColorItem", "#1A4A2A|||#4A1A1A|||")
ui.Update("Grid", "SetColVisibility", col) Shows or hides a DataGrid column. Value format: "ColumnName|1" (visible) or "ColumnName|0" (hidden). ui.Update("GridData", "SetColVisibility", "ID|0")
ui.Update("Grid", "RefreshGrid", "") Forces a full refresh of the DataGrid after all items and colors are added. Triggers Items.Refresh() + UpdateLayout() and reapplies all stored row styles. ui.Update("GridData", "RefreshGrid", "")
ui.Update("_Batch", "Cells", batch) Sends multiple commands in a single WM_COPYDATA message. Each line is control|property|value\n. Reduces IPC overhead for bulk operations. ui.Update("_Batch", "Cells", "GridData|AddItem|1|Name...`nGridData|AddColorItem|...")

4. Most Used Properties

  • Text: Text of a TextBox or textual content.
  • Content: Text of buttons, labels, and other ContentControls.
  • IsEnabled: Enables or disables the control ("True" / "False").
  • Visibility: Visible, Hidden, Collapsed.
  • Value: For Slider, ProgressBar, and ScrollBar.
  • Margin: Sets the outer margin as "left,top" or "left,top,right,bottom".
  • SelectedIndex: Selected index in lists and combos.
  • Background, Foreground, BorderBrush.
  • FontSize, FontWeight, Opacity.
  • Width, Height, ToolTip.

5. Common Controls

  • TextBox: TextChanged, Enter, GotFocus, LostFocus. Read/write via Text.
  • PasswordBox: PasswordChanged (mapped as TextChanged), Enter, GotFocus, LostFocus. Read via state["Name"].
  • Button: Click, Enter.
  • RepeatButton: Click (fires repeatedly while held). Delay and Interval configurable.
  • ToggleButton: Checked / Unchecked. Read IsChecked via state["Name"].
  • CheckBox / RadioButton: Checked / Unchecked.
  • ComboBox: AddItem, SelectionChanged.
  • Slider: ValueChanged (value 0-100).
  • ScrollBar: ValueChanged (horizontal and vertical). Supports read/write Value.
  • ProgressBar: Read/write Value (0-100).
  • DatePicker: DateChanged. Read SelectedDate from state.
  • Calendar: DateChanged (on selection). Read SelectedDate from state.
  • ListView: AddItem, AddRow, ClearItems, RemoveSelected, UpdateSelected, SelectionChanged, MouseDoubleClick.
  • DataGrid: AddItem, AddColorItem, Clear, RefreshGrid, SetColVisibility. Events: SelectionChanged, Click, MouseDoubleClick, RightClick, SelectedCellsChanged, CurrentCellChanged, BeginningEdit, CellEditEnding, RowEditEnding.

7. ListView and DataGrid in Practice

ListView: Full CRUD Cycle (Add, Edit, Delete)

The most robust way to manage a ListView is to maintain an array of objects in AHK and rebuild the list when changes occur. Use ClearItems followed by AddItem with pipe-separated values. 

; 1. REBUILD LIST (Call after Add, Edit, or Delete)
RebuildList() {
    global ui, Contacts
    ui.Update("ListaContactos", "ClearItems", "")
    for i, c in Contacts {
        ; Format: "index|Name|Phone|Email"
        ui.Update("ListaContactos", "AddItem", i . "|" . c.Name . "|" . c.Phone . "|" . c.Email)
    }
}

; 2. ADD OR EDIT
Add_Click(state, ctrl, event) {
    name := Trim(state["TxtName"])
    if (EditingIdx > 0) {
        Contacts[EditingIdx].Name := name ; Update existing
        EditingIdx := 0
        ui.Update("BtnAdd", "Content", "+ Add")
    } else {
        Contacts.Push({Name: name, Phone: state["TxtPhone"]}) ; Add new
    }
    RebuildList()
}

; 3. DELETE
Delete_Click(state, ctrl, event) {
    if (SelectedIdx > 0) {
        Contacts.Remove(SelectedIdx)
        SelectedIdx := 0
        RebuildList()
    }
}

ListView: Handling Selection & Parsing

When SelectionChanged triggers, state["ListaContactos"] returns the entire row as a pipe-separated string (e.g., "1|John|555-1234|john@test.com"). Use StrSplit to extract the index or specific columns. 

Lista_SelectionChanged(state, ctrl, event) {
    global ui, SelectedIdx, EditingIdx
    raw := state["ListaContactos"]

    if (raw = "") {
        SelectedIdx := 0
        ui.Update("BtnEdit", "IsEnabled", "False")
        ui.Update("BtnDelete", "IsEnabled", "False")
        return
    }

    ; Split by "|" to get the index (first column)
    campos := StrSplit(raw, "|")
    SelectedIdx := campos[1] + 0 ; Convert to number

    ; Enable buttons only if not currently editing
    if (SelectedIdx > 0 && EditingIdx = 0) {
        ui.Update("BtnEdit", "IsEnabled", "True")
        ui.Update("BtnDelete", "IsEnabled", "True")
    }
}

DataGrid: CRUD Pattern (Demo_DataGrid2)

The DataGrid does not include row data in the state dictionary. Use state["GridData_SelectedIndex"] to get the 0-based index and index into your AHK array. Maintain a parallel array of records in AHK. 

; Maintain array of records
global Records := []

; Add records (AHK-side)
LoadRecords(n) {
    global Records, NextID
    Loop % n {
        Records.Push(GenerateRec(NextID))
        NextID++
    }
}

; Render: clear + add items + optional colors
RenderGrid() {
    global Records, FilterText, ColorMode, ui
    ShowProc()
    ui.Update("GridData", "Clear", "")
    Loop % data.Length() {
        r := data[A_Index]
        ui.Update("GridData", "AddItem", RecToStr(r))
        if (ColorMode != "none")
            ui.Update("GridData", "AddColorItem", GetColors(r))
    }
    if (ColorMode != "none")
        ui.Update("GridData", "RefreshGrid", "")
    HideProc()
}

; Delete selected row using SelectedIndex
OnDelSel(state, ctrl, event) {
    idx := state["GridData_SelectedIndex"]
    if (idx = "" || idx < 0) return
    Records.RemoveAt(idx + 1)  ; 0-based → 1-based
    RenderGrid()
}

9. Moving Focus with Enter

The WPF engine automatically sends the Enter event when you press Enter in a TextBox, PasswordBox, or Button. You can use it to navigate forms like this: 

ui.OnEvent("TxtUser", "Enter", "Login_Enter")
ui.OnEvent("TxtPass", "Enter", "Login_Enter")

Login_Enter(state, ctrl, event)
{
    global ui
    if (ctrl = "TxtUser")
        ui.Focus("TxtPass")
    else if (ctrl = "TxtPass")
        ui.Focus("BtnLogin")
}

14. DataGrid: Commands, Colors, Column Visibility, and Bulk Operations

The DataGrid supports selection tracking (via SelectedIndex), per-cell color rules, column visibility toggling, and bulk operations through the _Batch/Cells mechanism. The Demo_DataGrid2.ahk demo showcases a performance-testing UI with 100–1000 records, CRUD, filtering, and three color modes.

14.1 DataGrid Commands

CommandDescriptionValue Format
ClearRemoves all rows from the grid.""
AddItemAdds a row. Each column separated by |."1|Name|email@ex.com|Dept|50000|City|Active"
AddColorItemSets per-column background colors for the last added row. Empty strings leave the default color. Must be called immediately after AddItem."#1A4A2A|||#4A1A1A|||" (one per column)
RefreshGridForces a full Items.Refresh() + UpdateLayout() pass and reapplies all stored row/cell styles. Call once after all items and colors are added.""
SetColVisibilityShows or hides a column by binding property name. Value is "ColumnName|1" (visible) or "ColumnName|0" (hidden)."ID|0" or "Salary|1"

14.2 Selection Handling

SelectionChanged sends the full state dictionary. The DataGrid adds state["GridData_SelectedIndex"] (0-based integer index, -1 if no selection). Unlike ListView, the grid does not include the row data in state["GridData"] — use SelectedIndex to index your AHK array. 

ui.OnEvent("GridData", "SelectionChanged", "OnSelChg")

OnSelChg(state, ctrl, event) {
    global ui
    idx := state["GridData_SelectedIndex"]
    if (idx = "" || idx < 0)
        ui.Update("LblSelected", "Text", "Selected: -")
    else
        ui.Update("LblSelected", "Text", "Selected: row " . idx)
}

14.3 Color Modes

The demo supports three color modes applied during grid rendering:

  • Random Rows: Each cell gets a random RGB color via Format("#{:02X}{:02X}{:02X}", r, g, b).
  • By Value: Conditional highlighting — high salary (>120k) gets green, low (<40k) red; Active status green, Suspended/Disabled red.
  • Column Colors: Each column gets a fixed tint.
; RenderGrid sends AddItem + AddColorItem for each row
Loop % data.Length() {
    r := data[A_Index]
    ui.Update("GridData", "AddItem", RecToStr(r))
    if (ColorMode != "none")
        ui.Update("GridData", "AddColorItem", GetColors(r))
}
if (ColorMode != "none")
    ui.Update("GridData", "RefreshGrid", "")  ; final style pass

14.4 Column Visibility Toggling

Each column button toggles its column's visibility. The button's opacity dims when the column is hidden. 

OnToggleCol(state, ctrl, event) {
    ; event argument contains the button name (e.g. "BtnColID")
    key := ColKeys[idx]         ; e.g. "ID"
    ColVis[key] := !ColVis[key]
    n := ColVis[key] ? "1" : "0"
    ui.Update("GridData", "SetColVisibility", key . "|" . n)
    ui.Update(ctrl, "Opacity", ColVis[key] ? "1" : "0.4")
}

14.5 Bulk Operations via _Batch/Cells

To avoid hundreds of individual SendMessage calls, you can pack multiple commands into a single _Batch/Cells update. Each line in the value has the format control|property|value\n. All lines are processed atomically in a single Dispatcher.Invoke call on the WPF UI thread. 

BatchRender() {
    batch := ""
    Loop % data.Length() {
        r := data[A_Index]
        batch .= "GridData|AddItem|" . RecToStr(r) . "`n"
        if (ColorMode != "none")
            batch .= "GridData|AddColorItem|" . GetColors(r) . "`n"
    }
    if (ColorMode != "none")
        batch .= "GridData|RefreshGrid|`n"
    if (batch != "")
        ui.Update("_Batch", "Cells", batch)
}

Pipe-safe parsing: The C# engine uses IndexOf to find the first two | separators, so values can contain pipe characters. The format is control|property|value\n where value is everything after the second |.

14.6 Performance Optimization (AddColorItem)

The original AddColorItem implementation iterated all rows and called Items.Refresh() + UpdateLayout() on every call, producing O(n²) behaviour. The optimized version:

  • Stores the style in a Tag dictionary keyed by row index.
  • Applies the style only to the last added row (the row just inserted by the preceding AddItem).
  • Defers the full style pass to a single RefreshGrid call after all items are added.

Result: O(1) per AddColorItem call instead of O(n²). Loading 1000 records with per-cell colors completes in seconds instead of hanging.

15. Centralized Theme System

The project provides a reusable theme system with two files: themes.ahk (defines all color palettes) and ThemeManager.ahk (manages applying and cycling themes). Add new themes by editing only themes.ahk — no code changes needed.

Setup and Usage

#Include %A_ScriptDir%\..\themes.ahk
#Include %A_ScriptDir%\..\ThemeManager.ahk

; 2. Initialize at startup
ui := new XAMLGUI("Demo.xaml")
InitThemeManager(ui)

; 3. Apply a theme by name
ApplyTheme("Navy")

; 4. Cycle to next theme (bind to a button)
ui.OnEvent("BtnTheme", "Click", "CycleTheme")

currentName := GetCurrentTheme()   ; returns e.g. "Teal"

SaveData() {

LoadData() {

The TitleBar.ahk module provides a reusable title bar with Minimize, Maximize/Restore, and Close buttons across all demos. Drag-to-move is enabled automatically by placing x:Name="TitleBar" on the title bar Border in XAML.

AHK API

InitTitleBar(ui, {title: "My App"})

; Full configuration
InitTitleBar(ui, {
    title:     "Inventory Dashboard",

17. FIFA Dashboard (Demo_Dashboard_FIFA.ahk)

A full-featured sports dashboard that connects to a local SQLite database (FIFA.db) and displays teams, stadiums, match schedules, and statistics through a WPF interface.

Architecture

The demo lives in demos/FIFA/ and uses three layers:

  • Data: FIFA.db (SQLite) — contains teams, stadiums, and match data
  • Logic: FIFA_DB.ahk + Class_SQLiteDB.ahk — SQL queries and data processing
  • UI: Dashboard_FIFA.xaml — modern dark WPF layout with navigation sidebar

Key Features

  • 7 navigation tabs (Home, Countries, Groups, Fixture, Stats, Stadiums)
  • Live countdown to next match
  • Country search/filter
  • 7 custom color themes (dashboard-specific, not using the centralized theme system)
  • Integrated TitleBar with BtnTheme (theme cycle), close/minimize buttons
  • Images from demos/FIFA/Assets/

Technical Notes

  • 32-bit SQLite DLL is required — AHK 1.1 Unicode is 32-bit and cannot load a 64-bit sqlite3.dll. The correct DLL is at demos/FIFA/Lib/sqlite3.dll.
  • #Include without explicit path fails when the working directory differs from the script directory. Always use #Include %A_ScriptDir%\Lib\Class_SQLiteDB.ahk.
  • exePath depth: Since the script is in demos/FIFA/, pass A_ScriptDir "\..\..\WPF_Runner.exe" to the XAMLGUI constructor.
  • The FIFA themes are self-contained (7 entries in Dashboard_FIFA.xaml) and incompatible with the 19-key centralized palette.

18. SystemInfo Dashboard (Demo_SystemInfo.ahk)

A system diagnostic dashboard that runs systeminfo and displays the results in a modern card-based WPF layout with per-card PNG icons.

How It Works

  • AHK runs systeminfo > file.txt via RunWait
  • Output is read with the OEM code page (DllCall("GetOEMCP")) to correctly decode accented characters from cmd.exe redirection
  • Spanish field names are mapped to English keys using Chr() for accented characters (Chr(0xED) for í, Chr(0xF3) for ó)
  • 12 key fields populate dedicated cards; all remaining fields appear in the "Extra Info" card

Layout

  • 6 cards: System, Processor, Memory, Storage, Network, Extra Info
  • Each card has a 72×72 PNG icon on a white rounded square, with a 26pt title to the right
  • Loading panel with detail text while systeminfo runs
  • Refresh button to re-run the command
  • Navy theme defaults defined in XAML Window.Resources (required because ApplyTheme() before Show() silently fails)

Technical Notes

  • OEM vs ANSI code page: cmd.exe > writes using the OEM code page (CP437 on this system), but FileRead defaults to ANSI (Windows-1252). This corrupts accented characters like ó → ¢. Fix: use FileRead, *P%oemCP% %file%.
  • Spanish field names: On Spanish Windows, systeminfo outputs "Nombre de host", "Versión del sistema operativo", "Memoria física total", etc. A mapping table normalizes them to English keys.
  • Icons are loaded from C:\AHK_WPF\Assets\ via relative path ../Assets/ from the XAML file.
  • JSON-like values from WPF events use Base64 encoding for safe transmission over WM_COPYDATA.

20. DataGrid Operations Demo (Demo_DataGrid2.ahk)

A performance-testing demo focused on bulk DataGrid operations with 100–1000+ records. Lives at C:\AHK_WPF\demos\Demo_DataGrid2.ahk + Demo_DataGrid2.xaml.

Controls

  • Load 100 / 200 / 500 / 1000: Adds records individually via separate AddItem calls. The UI thread stays responsive because events are dispatched asynchronously.
  • Batch 500: Sends all 500 records in a single _Batch/Cells message. All items arrive in one SendMessage and are processed atomically.
  • Clear All: Resets the record array and clears the grid.
  • Delete Sel / Delete Rnd: Deletes the selected row via SelectedIndex or a random row.
  • Random Rows / By Value / Column Colors: Three colouring modes applied during RenderGrid().
  • Filter: Filters all columns by text match. Rebuilds the grid with only matching records.
  • 7 Toggle Col buttons: Shows/hides each column via SetColVisibility.

Key Implementation Details

  • ShowProc / HideProc: All operations start with ShowProc() (sets status to "Processing...") and end with HideProc() (restores "Ready" or record count).
  • Color modes are applied inline during item addition; RefreshGrid is called once at the end.
  • Column visibility is tracked in an AHK associative array (ColVis). Toggle buttons dim to 0.4 opacity when hidden.
  • Filtering rebuilds the grid with only matching records; the original array is preserved.
  • The AsyncSendEventToAhk mechanism in Program_WPF.cs delegates SendMessage to a thread-pool thread, keeping the WPF UI thread responsive.

ComboBox Commands

CommandDescriptionExample
AddItemAdds a string item to the ComboBox.ui.Update("Combo", "AddItem", "Apple")
ClearItemsRemoves all items and resets selection to -1.ui.Update("Combo", "ClearItems", "")

State Values

When a SelectionChanged event fires, the state dictionary includes:

  • state["ComboName"] — The selected index (0-based, as string), or -1.
  • state["ComboName_SelectedIndex"] — Same as above (duplicate for consistency with DataGrid).
  • state["ComboName_Text"] — The display text of the selected item.

Implementation Details

  • Theme-aware: All ComboBoxes use DynamicResource for background, border, foreground, and dropdown colors. The Theme button cycles through all available themes.

  • Item tracking: AHK maintains parallel arrays (_dynItems, _fruitItems) to track item text and counts. The total item counter sums static (10) + dynamic + fruit items.
  • ClearItems engine support: Program_WPF.cs handles ClearItems on ComboBox by calling Items.Clear() + SelectedIndex = -1.
